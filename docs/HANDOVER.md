# Передача сайта покупателю

Практический чек-лист: что продаём, как передать и что обязательно поменять после передачи.
Документ для продавца; покупателю можно отдать его целиком — секретов здесь нет.

## 1. Что входит в сайт

- Публичная часть: главная с меню и 3D-сценой, оформление заказа, страница заказа по
  приватной ссылке, контакты, условия, политика конфиденциальности, лицензии.
- Кабинет владельца `/admin`: заказы со статусами, меню и цены, данные компании,
  игра и бонусы, персонаж, пароль и сессии.
- Сервер: пересчёт цен, проверка фото, идемпотентность заказа, защита приватных фото.
- Уведомления в Telegram (включаются двумя переменными окружения).
- Автоочистка старых заказов по расписанию.
- Тесты: 82 юнит-теста, 16 сквозных сценариев, проверка типов и сборка в CI.
- Исходный код, README с инструкцией запуска и развёртывания.

## 2. Что покупатель получает физически

| Вариант | Что передаётся | Кому подходит |
|---|---|---|
| **A. Ссылка** | Только адрес сайта, кабинет и пароль владельца | Показать, продать «как есть», без передачи кода |
| **B. Проект целиком** | Репозиторий + проект Vercel + база Neon + домен | Покупателю нужен полный контроль |
| **C. Только код** | Архив или репозиторий, покупатель разворачивает сам | Технически грамотный покупатель |

Вариант B — самый честный: покупатель владеет и кодом, и хостингом, и базой.

## 3. Передача по шагам (вариант B)

### 3.1 Репозиторий

1. GitHub → репозиторий → *Settings → General → Danger Zone → Transfer ownership*.
2. Либо покупатель делает форк, а вы архивируете код:

   ```bash
   git archive --format=zip --output=teply-box.zip HEAD
   ```

   В архиве нет `.env.local`, `data/`, `.next/` и `node_modules` — только исходники.

### 3.2 Хостинг Vercel

- **Передать проект:** Vercel → проект → *Settings → Advanced → Transfer Project*.
  Покупатель должен быть участником команды, куда передаётся проект.
- **Проще и надёжнее:** покупатель создаёт свой аккаунт Vercel, импортирует
  переданный репозиторий, вы переносите переменные окружения и домен. Старый
  проект удаляете после проверки.

### 3.3 База данных Neon

- **Передать проект:** Neon → проект → *Settings → Transfer project* на аккаунт покупателя.
- **Или перенести данные** в новую базу покупателя:

  ```bash
  pg_dump "postgres://...старая..." --no-owner --no-acl -f backup.sql
  psql "postgres://...новая..." -f backup.sql
  ```

  Затем в Vercel заменить `DATABASE_URL` и передеплоить.

### 3.4 Домен

Если домен уже куплен у вас: Vercel → проект → *Settings → Domains → Add*, затем
прописать у регистратора записи, которые покажет Vercel (обычно `A` на адрес Vercel
для корня и `CNAME` для `www`). Сертификат выпускается автоматически, обычно за минуты.

Если домена нет: покупатель покупает свой и привязывает так же. Бесплатный адрес
`*.vercel.app` работает всегда.

### 3.5 Переменные окружения

Переносить нужно все, что есть в *Settings → Environment Variables*:

`APP_URL`, `NEXT_PUBLIC_APP_URL`, `APP_SECRET`, `DATABASE_URL`, `OWNER_EMAIL`,
`OWNER_PASSWORD`, `OWNER_NAME`, `COOKIE_SECURE`, `DEMO_MODE`, `APP_TIMEZONE`,
`CRON_SECRET`, `RETENTION_DAYS`, при наличии — `TELEGRAM_BOT_TOKEN`,
`TELEGRAM_CHAT_ID`, `ASSISTANT_LLM_*`.

Значения секретов Vercel не показывает. После передачи их нужно **задать заново**,
а не копировать: см. раздел 5.

## 4. Что сделать до продажи (продавцу)

- [ ] Сменить пароль владельца в `/admin/access` — прежний обсуждался в переписке.
- [ ] Решить судьбу демо-заказа в кабинете: оставить как пример или удалить.
- [ ] Проверить тексты `/terms`, `/privacy`, `/contacts`, `/licenses`: там написано
      «учебный проект», «вымышленное кафе». Для реального бизнеса это нужно заменить.
- [ ] Решить, входит ли Telegram-бот: если да — передать бота покупателю (BotFather →
      *Transfer ownership*), если нет — просто не задавать `TELEGRAM_*`.
- [ ] Удалить из репозитория всё лишнее (`.neon`, `scratch-*.mjs`), если не нужны.
- [ ] Зафиксировать в договоре или расписке: что передаётся, кому принадлежат права
      на код и контент, есть ли поддержка после передачи.

## 5. Что сделать после передачи (покупателю)

- [ ] Сменить пароль владельца в `/admin/access`.
- [ ] Задать новый `APP_SECRET` (длинная случайная строка) и передеплоить —
      это разлогинит старые сессии.
- [ ] Задать новый `CRON_SECRET`.
- [ ] Выпустить новый токен Telegram-бота, если бот переходил вместе с сайтом.
- [ ] Проверить `APP_URL` — он должен совпадать с реальным адресом сайта
      (влияет на sitemap, robots и проверку Origin).
- [ ] Убедиться, что `DEMO_MODE=false`, иначе на экране входа показывается демо-пароль.
- [ ] Пройти чек-лист приёмки (раздел 7).

## 6. Ограничения, которые нужно назвать покупателю заранее

Честно, чтобы потом не было претензий:

- Онлайн-оплата не подключена: заказ подтверждает человек в кабинете.
- Автодеплоя из GitHub нет — обновления выкладываются вручную командой
  `vercel --prod` (или включаются в настройках Vercel).
- Фото: до 1,2 МБ на файл, до 3,6 МБ на весь заказ — ограничение хостинга.
- Защита от спама хранится в памяти инстанса, это «от грубого спама», не строгая гарантия.
- Заказы и фото удаляются автоматически через 90 дней (срок меняется переменной).
- Тестировалось в Edge/Chromium на десктопе и в мобильной эмуляции; реальные Safari
  и Firefox не проверялись.
- ИИ-помощник работает локально без ключей; LLM-режим не проверялся в бою.
- Бренд, меню, цены и тексты вымышленные — покупатель заменяет их в кабинете.

## 7. Чек-лист приёмки (покупатель проверяет сам)

1. Главная открывается, меню и цены совпадают с ожидаемыми.
2. Собирается заказ с добавками, сумма считается правильно.
3. Оформление проходит, появляется приватная ссылка на заказ.
4. Посторонний токен заказа отдаёт 404, фото без токена не открываются.
5. Заказ виден в кабинете, статус меняется, клиент видит изменения по своей ссылке.
6. Страница `/privacy` и `/terms` содержат данные покупателя, а не демо.
7. Вход в кабинет работает под новым паролем, старые сессии разлогинены.
8. Уведомления (если включены) приходят в нужный чат.
9. Мобильная версия: нет горизонтального скролла, кнопки нажимаются.
10. Домен открывается по HTTPS, `http://` перенаправляется на `https://`.

## 8. Как «прикрепить» сайт к сообщению

Сайт — это не файл, а адрес. В объявлении или переписке достаточно ссылки:
`https://<адрес-сайта>` — мессенджеры развернут её в превью с картинкой.

Если нужен именно файл (например, для отправки кода): архив из раздела 3.1.
Полный «архив сайта» с базой данных отправлять не нужно и небезопасно — в нём
персональные данные заказов.
