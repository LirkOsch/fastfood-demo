# Тёплый бокс — демо-кафе быстрого питания

Демонстрационный веб-проект вымышленного кафе: сайт с конструктором блюд, оформлением
заказа, приватной страницей заказа, кабинетом владельца и мини-игрой на 3D-подносе.

Всё в проекте — демо: название, адрес, телефон, цены, контакты и модель 3D — оригинальные
или вымышленные. Реальные кафе и их данные не использованы.

## Что внутри

**Клиентская часть**
- Меню по категориям: бургеры, шаурма, пицца, закуски, напитки, десерты и «Своё блюдо».
- Конструктор: размер порции, платные добавки («двойная начинка» +35%, «второй соус» +15%).
- Корзина: переживает перезагрузку, одинаковые позиции сливаются, разные конфигурации
  остаются отдельными, удаление с отменой.
- Смешанный заказ: известная сумма считается отдельно, позиции «по запросу» никогда не
  показываются как бесплатные.
- Оформление: имя, телефон, доставка или самовывоз, выезд за город, дата и время,
  до трёх фото, комментарий, согласие. Черновик и фото восстанавливаются после перезагрузки.
- Приватная страница заказа по непредсказуемому токену: статус, итоговая цена, время,
  сообщения кухни, фото. Обновления владельца видны по той же ссылке.
- Мини-игра «протри поднос» после выполнения заказа: режимы вращения и очистки,
  прогресс, бонусный код.

**ИИ-помощник**
- Кнопка «Спросить» на публичных страницах: меню и цены, состав, доставка,
  самовывоз, минимальный заказ, оплата, своё блюдо, бонусы.
- Статус заказа читается по приватной ссылке: имя, телефон и адрес в ответ не попадают.
- Цены берутся только из настроек кафе, поэтому помощник не может выдумать сумму.
- Может предложить добавить блюдо в корзину — кнопкой, без скрытых действий.
- Работает без ключей и интернета на локальном детерминированном ядре.
  Необязательный LLM включается переменными `ASSISTANT_LLM_*` и отвечает только там,
  где ядро не распознало вопрос.

**Кабинет владельца** (`/admin`)
- Заказы: поиск, фильтр по статусу, обновление списка, детальная карточка.
- Статусы: новый → подтверждён → выполнен / отменён.
- Для «Подтверждён» обязательны итоговая цена и согласованное время.
- Внутренние заметки, которых не видит клиент.
- Удаление заказа с подтверждением и фото.
- Настройки: меню и цены, данные компании, игра, персонаж, доступ и пароль.

**Технически**
- Next.js 16 (App Router), React 19, TypeScript.
- Three.js + React Three Fiber + Drei: процедурные GLB-модели, ограничение камеры,
  сброс ракурса, тени в сцене, постер-фолбэк, поддержка `prefers-reduced-motion`.
- Встроенная PostgreSQL (PGlite) для локального запуска; `DATABASE_URL` для продакшена.
- Фото сжимаются в браузере (лимит запроса Vercel), затем на сервере в WebP,
  проверяется реальный формат, доступ только по токену
  заказа или через авторизованный маршрут админки.
- Auth: bcrypt + хешированные сессии в HttpOnly-cookie; смена пароля отзывает все сессии.
- Идемпотентная отправка заказа по ключу.
- PWA: манифест, иконки, service worker, офлайн-страница, sitemap и robots.

## Быстрый старт

```bash
npm install
cp .env.example .env.local   # Windows: copy .env.example .env.local
npm run dev
```

Открыть http://localhost:3000

База PGlite создаётся автоматически в `./data/pglite` и заполняется настройками
и демо-пользователем при первом запуске.

### Демо-доступ в кабинет

```
URL:      http://localhost:3000/admin/login
E-mail:   owner@teplybox.example
Пароль:   teplybox-demo-2026
```

Значения берутся из `.env.local` (`OWNER_EMAIL`, `OWNER_PASSWORD`).

## Публикация на Vercel

Полная версия (заказы, статусы, кабинет, помощник) требует сервера — GitHub Pages
такого не умеет. Проект запускается на Vercel как обычное Next.js-приложение.

1. **Аккаунты.** Регистрация на [vercel.com](https://vercel.com) (через GitHub) и
   на [neon.tech](https://neon.tech) — внешняя база PostgreSQL. На Vercel файловая
   система недоступна между запусками, поэтому встроенная PGlite не подходит.
2. **База.** В Neon создайте проект, скопируйте строку подключения вида
   `postgres://user:pass@host/dbname?sslmode=require`.
3. **Проект.** Vercel → *Add New… → Project* → импорт репозитория
   `LirkOsch/fastfood-demo`, framework preset *Next.js*.
4. **Переменные окружения** (Settings → Environment Variables):

   | Переменная | Значение |
   |---|---|
   | `APP_URL` | `https://<имя-проекта>.vercel.app` |
   | `COOKIE_SECURE` | `true` |
   | `DATABASE_URL` | строка из Neon |
   | `OWNER_EMAIL`, `OWNER_PASSWORD`, `OWNER_NAME` | данные первого владельца |
   | `DEMO_MODE` | `false` (не показывать демо-доступ) |
   | `APP_TIMEZONE` | `Europe/Samara` |

   Необязательно: `ASSISTANT_LLM_KEY/URL/MODEL` для LLM-режима помощника.
5. **Deploy.** При первом запуске приложение само создаст таблицы и учётную
   запись владельца. После первого деплоя убедитесь, что `APP_URL` совпадает с
   финальным адресом (нужен для sitemap, robots и проверки Origin).

Ограничения Vercel Hobby, которые учитываются в коде:

- тело запроса — 4.5 МБ, поэтому фото сжимаются **в браузере** до 4 МБ
  (`src/lib/client/photos.ts`), а сервер повторно проверяет формат и жмёт;
- счётчики лимитов живут в памяти инстанса и считаются раздельно при
  нескольких инстансах — для демо это допустимо;
- время функции до 300 с, память до 2 ГБ (нам нужно заметно меньше).

## Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | Dev-сервер |
| `npm run build` | Production-сборка |

## Структура

```
src/app          маршруты (публичные, /admin, /api)
src/components   UI: landing, cart, checkout, order, game, admin, three, assistant
src/lib          цены, валидация, заказы, auth, БД, настройки, помощник
db/schema.sql    схема базы
public           иконки, модели, шрифты, service worker
tests            unit и e2e
scripts          генерация моделей, иконок, OG-картинки
```

## Настройки по умолчанию

- Минимальный заказ: 500 ₽ (только по позициям с известной ценой).
- Доставка по городу: 149 ₽, выезд за город: 300 ₽.
- «Двойная начинка»: +35%, «второй соус»: +15% (округление до рубля).
- Часы работы, адрес, телефон и тексты меняются в кабинете владельца.

## Ограничения демо

- Данные вымышленные; оплата не подключена, заказ подтверждает человек.
- 3D-модели процедурные и упрощённые, это не фотографичный рендер.
- Проверено в Edge/Chromium на десктопе и в мобильной эмуляции. Реальные мобильные
  устройства, Safari и Firefox не тестировались.
- LLM-режим помощника написан, но без API-ключа не проверялся. Локальное ядро
  покрыто unit- и e2e-тестами.
- Figma-макет и `.blend`-файлы не приложены: исходники — GLB и скрипты-генераторы.
- Лимиты Vercel: тело запроса 4.5 МБ (фото сжимаются в браузере), счётчики
  лимитов разделяются между инстансами. См. раздел «Публикация на Vercel».
